Security Boundary Architecture

What Tripline Checks that ArmorIQ Does Not

Three defense surfaces enforced inside the tool boundary.
1. Path Containment
Blocks file path traversal outside repository root with open-then-verify file descriptor TOCTOU checks.
DP-01: DENIED (PATH_OUTSIDE_ROOT)
2. Egress Canary
Quarantines outbound arguments and comments attempting to leak planted secrets.
IE-01: HELD (egress_canary_hit)
3. Signed Witness
Reconciles execution counts via append-only HMAC chain into signed canonical receipts.
Proof: Canonical SHA-256 + HMAC

Boundary Responsibilities

Separation of concerns between ArmorIQ authorizer and Tripline evidence layer.
ArmorIQ Authorizer

Role: External tool-level authorizer and plan constraints evaluator.

  • Checks caller identity and tool permissions via session.check()
  • Enforces tool whitelist and coarse policy rules
  • Returns ALLOW / DENY decisions at the boundary
  • Does not inspect filesystem paths or analyze argument payloads
Tripline Evidence Layer

Role: In-depth runtime enforcement and cryptographic witness.

  • Enforces path containment jail using open-then-verify fd checks
  • Deep-scans outbound arguments for Tier-1 and Tier-2 canary tokens
  • Maintains tamper-evident HMAC hash chain of executed calls
  • Generates canonical 10-field SHA-256 signed incident receipts

// ALLOWED IS NOT SAFE

Authorized doesn't mean harmless.

In our real demo runs, ArmorIQ allowed both attacks. Why? Because ArmorIQ is designed to verify whether an AI agent holds permission to invoke a specific tool like read_file or github_post_issue.

ArmorIQ does not inspect whether the file path traverses ../../.ssh/ or whether a pull request comment contains an injected canary payload. The danger was in the arguments.

Tripline inspects the arguments, restricts the sandbox boundary, and signs the proof.

// QUESTIONS & ARCHITECTURAL RIGOR

Frequently answered questions.

Direct explanations addressing questions security auditors and evaluators ask during inspection.

01. Why does ArmorIQ allow these actions if they are dangerous? expand_more
ArmorIQ performs credential and policy delegation: it answers whether a designated agent role holds the permission to invoke a general tool (e.g., read_file or post_comment). It does not evaluate dynamic runtime arguments such as jail-breaking directory paths or canary tokens embedded in body text. Tripline acts as the downstream gatekeeper that inspects these parameters.
02. What happens if Tripline itself crashes or fails? expand_more
Tripline defaults strictly to fail-closed. If any evaluation hook raises an unhandled exception or times out, the witness execution counter remains at 0 and the downstream tool is never dispatched. A failure receipt is immediately written with an error verdict.
03. Can an agent tamper with or forge its own receipt? expand_more
No. Receipts are calculated outside the agent’s execution sandbox using a separate HMAC secret key not accessible to the agent. The JSON canonicalization (RFC-8785) ensures that changing even a single whitespace character or field value invalidates the cryptographic signature.
04. What is the “M2 stub mode” mentioned in the header? expand_more
To ensure 100% deterministic reproducibility for judge audits, the M2 evaluation benchmark uses recorded, forced-compliance stubs rather than a non-deterministic live LLM. Every run uses identical input vectors and produces verifiable, identical hash results without API rate limits or drift.
05. How does Tripline differ from traditional Linux auditd or eBPF? expand_more
Linux auditd logs raw kernel syscalls but has zero contextual awareness of AI prompts, agent intention, or delegation policies. Tripline bridges prompt context (C0) with tool invocations (C1) and produces portable, cryptographically signed receipts that developers and auditors can review without kernel access.
06. Can we use Tripline without ArmorIQ? expand_more
Yes. Tripline is modular and provides standalone containment, path jail enforcement, and receipt generation. However, when paired with ArmorIQ, operators obtain full-spectrum coverage: verified upstream identity delegation coupled with forensic downstream containment.

Four Stacked Defense Planes

PLANE 1

Agent (Orchestrator & Crew)

Language model, pre-ingestion trusted planner, and scoped sub-agents (reader & responder). Proposes tool calls.

PLANE 2 (ARMORIQ)

ArmorIQ Platform

Intent Authorization Proxy, signed intent tokens, and policy evaluation. Denies out-of-plan tools before execution.

PLANE 3 (TRIPLINE)

Tripline MCP Boundary

In-MCP Path Jail (detects traversal and escape attempts) and Outbound Egress Gateway (catches canary leak attempts).

PLANE 4 (EVIDENCE)

Witness & Receipts

Append-only HMAC-SHA256 witness hash chain and canonical JSON forensic incident receipts for every blocked action.

// ARCHITECTURAL ATTRIBUTION

What Tripline Built vs What ArmorIQ Provides

ArmorIQ Platform & SDK
  • Plan capture (capture_plan) and Merkle hash verification
  • Intent authorization tokens (get_intent_token) issued by IAP
  • Platform policy evaluation and explicit deny enforcement
  • Per-user attribution binding via user_email / for_user()
Tripline Containment & Evidence Layer
  • Autonomous LLM issue triage loop with trusted pre-ingestion planner
  • In-MCP Path Jail (percent-decode, user-tilde expansion, inode canonicalization)
  • Outbound Egress Canary Gateway detecting prompt-injected data leaks
  • Append-only HMAC-SHA256 witness hash chain & signed incident receipts
Honest Security Disclosures:

• Attacks within plan: Plan binding restricts tool names; it cannot distinguish safe file reads from malicious ones. That is why Tripline Path Jail exists.

• Signatures: Receipts use symmetric HMAC-SHA256 keys. An entity with the witness key could forge a receipt; asymmetric Ed25519 is used for agent delegations.

• Sandbox isolation: All target repos and SSH key files are fake fixtures.

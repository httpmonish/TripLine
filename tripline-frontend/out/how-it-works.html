// ARCHITECTURE & EXECUTION STORY

An AI agent proposes an action.
TripLine helps enforce where that action can go.

An AI agent’s intention is not the same as permission to execute. When an LLM generates a tool call, reads a file, or initiates network egress, TripLine and ArmorIQ enforce two distinct, independent security perimeters.

// SCENE 2 & 3 — PROPOSAL & AUTHORIZATION

From Agent Intent to ArmorIQ Policy Gate

When an AI agent (such as TripLine’s maintainer triage crew) processes an issue, it translates unstructured task text into a normalized tool proposal. Before any tool code is dispatched, the request arrives at the ArmorIQ SDK boundary.

ALLOW (Tool Call In Plan)

ArmorIQ verifies that the proposed tool name belongs to the active session plan allowlist. Authorization succeeds and the request proceeds to TripLine containment.

DENY (Out of Plan / Prohibited)

The tool call is blocked immediately upstream (e.g. delete_branch requested by triage reader). 0 MCP tool calls are made.

UNAVAILABLE / Fail-Closed Default

If remote credentials or network connectivity are absent, TripLine refuses to simulate false approval and enforces fail-closed containment.

Real SDK Integration (`armoriq_helper.py`)
# 1. Initialize ArmorIQ SDK in direct Mode B
client = ArmorIQClient(api_key=ARMORIQ_API_KEY, mode="sdk")

# 2. Start session with registered triage plan
session = client.start_session(
    SessionOptions(mode="sdk", default_mcp_name="tripline-mcp")
)

# 3. Synchronous policy check before dispatch
enforce_result = session.check(
    tool_name="delete_branch",
    args={"name": "stale/old-experiment"}
)

if not enforce_result.allowed:
    # HALT: Never call MCP tool. Preserve evidence.
    mint_receipt(status="DENIED-ARMORIQ", reason=enforce_result.reason)

Layer-by-Layer Security Guarantees

Every layer answers a distinct security question and implements a different defensive mechanism.

Security LayerMain QuestionPossible OutcomesReal ImplementationWhat It Does NOT Guarantee
ArmorIQ AuthorizationIs this proposed operation authorized under registered session policy?ALLOW, DENY, or UNAVAILABLEarmoriq_helper.py (`session.check`)Does not inspect file descriptor inodes, symlink escapes, or network payload secrets.
TripLine Path JailDoes the resolved file path escape the trusted sandbox boundary?IN_BOUNDS or PATH_OUTSIDE_ROOTmcp/common/jail.py (kernel `fstat`)Does not evaluate user roles, business policy, or network egress payloads.
TripLine Egress GatewayDoes outbound parameter text contain seeded canary exfiltration tokens?ALLOW or HOLD (Quarantine)gateway/taint_rule.pyDoes not detect fragmented, polymorphic, or Base64-encoded secret payloads.
Sandboxed Execution LayerDid the permitted tool actually execute, and what was its return value?EXIT 0 or EXIT 1 (ERROR)Subprocess execution inside MCP serverExecution success does not imply that receipts have been independently verified offline.
Forensic Witness LedgerWhat cryptographic proof was produced, and does its HMAC signature verify?VERIFIED or TAMPER_DETECTEDreceipts/verify.py & `witness/chain.py`Witness verification proves what happened; it does not undo an already executed operation.

## 1. Overview & Architectural Principle

TripLine is an interactive cybersecurity investigation and governed action platform. The backend is the **sole authoritative source of truth** for:
- Agent planning, scoped roles, and tool proposals.
- ArmorIQ upstream authorization decisions (`ALLOW`, `DENY`, or infrastructure unavailability).
- Independent TripLine containment decisions (in-MCP path-jail boundary, egress canaries).
- Tool dispatch state (`EXECUTED`, `BLOCKED`, `HELD`, or `FAILED`).
- Cryptographic evidence, witness chains (HMAC-SHA256), and signed security receipts.
- REA (Reverse Engineer Anything) static software analysis on preapproved synthetic targets.

No frontend component may simulate decisions, fake verification results, fabricate hashes, or present placeholder counts as live observations.

## 3. Discovered Security & Execution Controls

1. **Authorization Independence:** ArmorIQ decisions and TripLine path-jail / egress containment decisions are logged and evaluated separately. ArmorIQ is the upstream policy authority; TripLine MCP is the local parameter and sandbox boundary.
2. **Fail-Closed Gate:** If ArmorIQ credentials or live gates are absent, live executions fail closed with HTTP 403. Offline replay and deterministic benchmarks remain functional.
3. **Receipt Custody:** Receipts are signed server-side using HMAC-SHA256 (`TRIPLINE_RECEIPT_SECRET_KEY`) or Ed25519 private keys. No private keys or HMAC witness secrets are ever sent to client browsers.
4. **Job Streaming vs Run Events:** 
   - `/api/jobs/{job_id}/events` streams line-by-line CLI output of running subprocesses.
   - `/api/agent/runs/{run_id}/events` streams structured JSONL events of completed/recorded agent triage runs.
   - Live runs initiate a job, stream job progress, and subsequently correlate with the resulting run manifest.
